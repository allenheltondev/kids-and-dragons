# Project audit — 2026-10-23

A hardening and maintainability pass across the server, the shared engine, the client and the
infrastructure. The September audit's guidance still holds and was followed: keep the
local/AWS adapter seams, keep the state library, do not split services. Four read-only reviews
(server request path, engine, client runtime, infra/CI) were each checked against the code before
anything changed; findings that did not survive that check are not listed.

The engine is not slow. A mid-fight `RunState` is about 5 KB, and a no-op `applyIntent`,
`structuredClone` included, takes about 40 µs. The gains were in I/O, races and per-frame client
work, not in rules code.

## Repaired in this pass

Each item is one commit on the branch, with its reasoning in the message.

**Correctness at the table**

- **A patch that no longer fit the mirror froze the screen for good.** The sequencer dropped the
  message, the gap resync replayed the same failing patch forever, and `synced` stayed true, so
  the frozen state looked live. Now it reports `onDesync`, applies nothing more, and the store
  fetches a full snapshot (decisions wait for it, #413). The hole-filling buffer is capped at
  200 messages.
- **Two phones committing at once could get a 500.** DynamoDB cancels such transactions with
  `TransactionConflict`, which was not counted as a lost race. It now returns `STALE_SEQ`, and
  any other cancellation reason still throws.
- **False `STALE_SEQ`.** `getState` reads strongly consistent. The action is gated on that seq.
- **Malformed intents.** A `MOVE` with no `to` threw a `TypeError` in the encounter (a 500 on
  every retry). `ready: "yes"`, `accept: "no"` and any JSON as `mode` were stored. An unknown
  intent type was accepted and moved the seq. All are now refused as `ILLEGAL` by
  `checkIntentShape` in `dispatch`, and the switch is exhaustive.

**Security and data**

- **A device-token rotation could undo a revocation.** It re-put the binding read at resolve
  time. Rotation now goes through `repo.rotateDevice`, a conditional update that refuses a
  revoked binding.
- **`/api/progression/spend` skipped the seq gate.** A double tap spent two points. It now
  requires `seq`.
- **Request bodies.** The Lambda refuses bodies over 256 KB, as the dev server already did.
  A logged intent is kept only at a real intent's size, and a replay sends only protocol fields.
- **Prod table and user pool.** Both have deletion protection, and the table has point-in-time
  recovery. The old comment ruling PITR out was mistaken: a restore goes to a new table, and one
  family's rows are copied back from it.
- **Dependencies.** npm advisories went from 9 (3 critical, 2 high) to 0, all in-range bumps.
  Dependabot now covers npm. npm 10's `audit fix` crashes on this tree (arborist
  `#loadPeerSet`), so the lockfile was resolved with npm 11 and verified with npm 10 `npm ci`.

**CI and deploy**

- **A manual prod dispatch could ship any ref.** The guard now requires an ancestor of `main`
  and pins that SHA for the checkout.
- **A failed `changes` job silently skipped `build`.** A skipped job satisfies a required check.
  `build-result` now holds the required name and fails in that case, as `e2e-result` already
  did.
- **A full-suite flake.** Four journey CLI tests had vitest's 5s default while their subprocess
  needed more.

**Latency and resource use**

- **Outbound deadlines.** The DynamoDB client gets 1s connect, 3s request and 3 attempts.
  AppSync publish aborts after 2s.
- **Hot-path reads.** A tap reads state, run and player in parallel, two round trips fewer.
- **TV memory.** Backdrops beyond the last two are unloaded. Before, a TV gained about 100 MB per
  chapter and never let go.
- **Per-frame and per-patch work on the client:**
  - The board's turn ring is drawn once, then moved and faded.
  - The empty trail layer is no longer cleared every frame.
  - The dice scramble stops when the dice settle.
  - CombatPanel's layout hooks re-measure only when their element or turn changes.
  - The chapter map layout is cached per chapter.

## Needs the owner: settings and deploys only you can do

These were found and verified, but they need AWS or GitHub access, or a decision this pass
should not make alone. They are listed most urgent first.

1. **The staging deploy role can make itself account admin.** `infra/github-oidc.yaml`
   `IamKadRoles` allows `CreateRole`, `AttachRolePolicy`, `PutRolePolicy` and `PassRole` on
   `role/kad-staging-*`, plus `lambda:*` on `kad-staging-*`. There is no permissions boundary.
   A collaborator's PR runs with that role (deploy.yml), so it could create a role, attach
   `AdministratorAccess`, pass it to a Lambda and invoke it. Staging and prod share the account.
   The `DenyTouchingTheDeployRolesThemselves` statement does not cover this.
   - **Fix:** a `kad-boundary` managed policy, an `iam:PermissionsBoundary` condition on the
     three write actions, and `PermissionsBoundary` on every function and schedule role in
     `template.yaml`.
   - It was not changed here because it is deployed by hand and a mistake breaks staging
     deploys. It should be the next change made.
2. **Set Production's deployment branches to `main` only** (GitHub environment settings). A PR
   can edit its workflow into `environment: Production`, and nothing in the repo can stop that.
   docs/deploy.md now says so.
3. **Rate limiting and an open edge.** There is no WAF, and the execute-api endpoint is reachable
   around CloudFront. Cognito's `COGNITO_DEFAULT` email cap (about 50 a day) can be exhausted by
   scripted sign-ups, which locks out every family's sign-in.
   - **Fix:** a WAFv2 rate rule on `/api/*` and on the user pool, `DisableExecuteApiEndpoint`
     (or refusing requests without `x-kad-origin`), and SES for email.
4. **No CSP,** and `/api/*`, `/content/*` and `/assets/*` get no security headers at all. This
   needs a custom ResponseHeadersPolicy on all four behaviors.
5. **No alarms and no DLQ on the sweep schedule,** which carries the 7-day deletion promise. Log
   retention is said to be managed outside the repo, but this pass could not verify it.

## Validation

- **Typecheck:** clean across shared, canon, server, client and tools.
- **Tests:** 5,493 passed and 11 skipped. The baseline was 5,454 passed and 1 failed (the flake
  above).
- **Static gates:** `content:validate`, cfn-lint, the Lambda bundles and `npm audit` (0) pass.
  First paint is 309/315 KB.
- **New regression tests fail on the code they replace.** The desync, intent-shape (in fight),
  layout-hook, parallel-read and dice tests were each run against the old code.
- **Layout e2e** (`layout-fit`, `phone-fit`, `tablet-fit`): 14 of 14 passed in Chromium after the
  CombatPanel change.
- **Golden re-taken once.** The Gemfall wolf-fight board golden: a diff of the scene-graph
  signature shows only the turn ring's line moved, to the same world box, color and width.
- **Not run here:**
  - The DynamoDB Local contract suite: its download host is outside this session's network
    policy. CI's build job runs it, and `rotateDevice`'s condition expression needs it.
  - No deploy, no live AWS check, and no measurement on physical devices.
