# Project audit — 2026-09-08

The foundations are sound: a pure, authoritative rules engine; transactional state/event writes; shared game behavior across the two layouts; and a renderer loaded separately from the controls. Keep those boundaries. The main stability risk is asynchronous recovery, not a lack of frameworks. This was a broad engineering pass with targeted repairs, not an exhaustive security review or physical-device certification.

## Repaired in this pass

- Delayed HTTP snapshots could overwrite newer realtime state, including after leaving. Sequencer resets now reject older snapshots and disposed instances.
- Leaving during an in-flight display attach could put the user back in the room. Leaving now invalidates that attachment.
- A previous room's resync completion could clear a newer room's in-flight resync marker. Cleanup now checks promise identity.
- Repeated errors and late callbacks from abandoned connections could schedule duplicate reconnects or report a closed channel as open. Callbacks now check source ownership.
- Broadcast recovery stopped after one failed fetch and background recovery could reject without a handler. Recovery now retries until the promised sequence arrives or the session ends; background failures are handled.
- Two art tests generated invalid Python string literals for Windows paths. Paths are now escaped.
- Unbounded test-worker concurrency produced intermittent five-second timeouts under concurrent browser/build load. Workers are capped at four; test deadlines and coverage floors are unchanged.
- JavaScript coverage included Python, CSS, and Markdown. Its input globs now select JavaScript/TypeScript files.
- Updated vulnerable dependencies: js-yaml 4.3.2, @xmldom/xmldom 0.8.15, qs 6.16.0, fast-uri 3.1.7, nanoid 3.3.18. Full npm audit reports zero known vulnerabilities at the time of this pass.

Five regression tests cover snapshot ordering/disposal, pending attach cancellation, post-leave resync, duplicate transport callbacks, and retrying failed broadcast recovery.

## Follow-up completed

1. **Production config discovery:** only HTTP 404 selects local SSE. Network/server errors and malformed successful responses remain failures. Successful config is cached; failed discovery is retried with backoff, and leaving cancels pending retries. The room snapshot remains usable during recovery. Tests cover local 404, server/network errors, invalid payloads, eventual production transport selection, and cancellation.
2. **Renderer failure containment:** Pixi startup now handles rejection immediately and cleans up partially initialized resources. A local React error boundary contains a failed lazy renderer import. Both paths show an accessible fallback while preserving the game panels. Regression tests cover failed initialization, failed chunk import with usable controls, and initialization settling after unmount/Strict Mode cleanup.
3. **One resync owner:** the store serializes fetches, coalesces overlapping requests into another catch-up from the latest sequence, and retries failures with backoff. The channel forwards reconnect notifications without maintaining a second fetch queue. The sequencer retains patch ordering and presentation timing. Gap and broadcast checks respect pending retry backoff; session replacement/leave cancels retry work. Tests cover overlapping recovery, failed reconnect catch-up without another message, cancellation, and repeated gap notifications during an outage.
4. **Honest CLI coverage:** a Vitest-only pre-transform changes the initial shebang to a same-length comment before Vite prepends SSR imports. Scripts on disk remain directly executable. All five formerly omitted CLI files are now included, and five regression cases check their Node syntax and transformed parsing. They report 0% because subprocess execution is not collected by Vitest; this is visible in the denominator rather than silently omitted. Coverage floors are unchanged.
5. **Chapter test driver:** the full browser run exposed a valid dice branch into combat that the general chapter test could not play. Extracted the existing dedicated fight driver and reused it in the chapter walk. The test now plays actual combat cards instead of incorrectly declaring that nobody has anything to tap; outcome and timeout assertions remain intact.

PR integration note: current main independently repaired and expanded the combat driver. The PR preserves that newer implementation rather than replacing it with the earlier extraction above. It also preserves main's request timeouts, audio controls, and performance instrumentation. Browser startup now waits for `/api/health` through Vite, preventing a ready client from racing an API that is still starting.

## Responsiveness and complexity

- Home-screen checks at 320×568, 390×844, 844×390, and 1920×1080 found no horizontal document overflow or uncaught page errors. This does not establish frame rate or full-flow accessibility on real phones.
- Production entry JavaScript is approximately 349 kB / 104 kB gzip. PixiStage is a separate approximately 231 kB / 68 kB gzip chunk; Rive WASM is approximately 1.99 MB / 750 kB gzip. Preserve deferred rendering and measure art/GPU cost on the actual TV and phones before changing bundling.
- The Pixi stage already caps pixel density, stops its ticker for hidden/zero-sized surfaces, and releases gesture listeners. Those are useful optimizations already present, not changes from this audit.
- Keep the local/AWS adapter seams: they share meaningful behavior and contract tests. Do not split this into more services or replace the state library to make it appear more modern.
- Long historical comments in store/rendering code obscure relatively small implementations. Shorten them when touching those functions and move past incident narratives into documentation; a wholesale comment rewrite would make this corrective diff harder to review.
